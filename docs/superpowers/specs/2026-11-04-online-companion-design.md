# Online iPhone companion

Chat-approved: private Cloudflare HTTPS companion with alarm sync, shared notes, a focus timer, Send to Sudo, and optional iPhone battery status. Preserve island design/motion; fix repeated video/artwork switching separately.

Single-person service at a stable workers.dev origin. Cloudflare Worker + SQLite Durable Object stores a rolling seven-day alarm schedule, note/focus state, bounded phone inbox and optional battery report. Desktop publishes while running; phone can read the remaining stored coverage while PC sleeps. Expired/missing coverage yields an error, never an empty schedule. Show last PC contact/source update so cached data is explicit. Phone Clock still needs a Shortcut run; no instant push, native iOS app, remote phone control or phone-tested claim.

Separate random desktop secret (Cloudflare secret / Windows Credential Manager) and revocable phone capability (hashed server-side). Pair via expiring one-use random fragment code; phone claims it over same-origin HTTPS, clears fragment and stores its key locally. No secrets in logs/artifacts; no public listing/registration; no arbitrary PC execution/opening URLs. Browser origin limited to service origin. Request/body/queue limits, authenticated roles and no-store API responses.

Cloud state: `note:{text,updatedAt}`, `focus:{remaining,deadline,minutes,updatedAt}`, `inbox:[{id,text,createdAt}]`, `battery:{percent,charging,updatedAt}|null`, `lastDesktopAt`, schedule. Focus deadlines use epoch ms. Note/focus LWW timestamps generated by server for phone actions; desktop publishes only changed fields, matching remote revisions/timestamps without echo. Reject implausible clocks rather than overwrite. Inbox is bounded and offers explicit dismiss/copy in desktop Settings; nothing opens automatically.

API contract:
- `POST /v1/desktop/sync` desktop key; body `{schedule:{generatedAt,coverageUntil,timeZone,alarms:[{id,label,at,time,utcOffset}]},note?:{text,updatedAt},focus?:{remaining,deadline,minutes,updatedAt}}`; returns public state below. Validate horizon<=8days, <=2000alarms, <=512KiB.
- `GET /v1/state` desktop or phone; returns `{note,focus,inbox,battery,lastDesktopAt,coverageUntil,sourceUpdatedAt,phonePaired,lastImportedAt,importedCount}`. No desktop token/phone hash/pairing code/schedule list.
- `POST /v1/pair/new` desktop; returns `{pairUrl,expiresAt}` code in `/#pair=...`; expires10min. `POST /v1/pair/claim` no auth with `{code}` returns `{phoneKey}`; one-use, keep at most one paired phone capability (new claim revokes old).
- `POST /v1/revoke` desktop; revoke phone and pending pairing.
- `GET /v1/alarms` phone; existing `sudo.iphone-alarms.v1` manifest with ownerPrefix, UTC offset, revision, generatedAt/validUntil freshly generated, sourceUpdatedAt,coverageUntil,alarmCount,alarms,ackUrl. Next24h, >60s lead, refuse differing alarm offsets. Owned prefix stable per service.
- `POST /v1/ack` phone; `{revision,createdCount}` served revision/count matching within10min, update import status.
- `POST /v1/action` desktop or phone; discriminated union `{type:'note',text}`, `{type:'focus',action:'start'|'pause'|'reset',minutes?:number}`, `{type:'send',text}`, `{type:'dismiss',id}`, `{type:'battery',percent,charging}`. Battery phone only. Text/note<=2000, inbox<=50, minutes1..180; returns public state. Only validated capabilities; no executable commands.

Phone browser: static polished mobile page served by Worker, pair/unpair view, shared note editor, focus controls/deadline countdown, Send to Sudo input, optional battery Shortcut instructions, Clock sync values + recipe accessible in a separate section. Tokens hidden by default. API claims alone never imply actual Clock ringing.

Desktop native: `companion_status`, `companion_connect(url,key)`, `companion_disconnect`, `companion_request(path,method,body?)`; island-only. Secrets never returned in status. Strict workers.dev HTTPS configured origin, exact paths/methods, no redirects, bounded body/response, 10s timeout, blocking network off UI thread. Disconnect removes token/config; no cloud worker deletion.

Desktop frontend: online section in Alarm Settings, toggles connection via stored native config, generates pairing QR, shows state/inbox/battery, shared note/focus connect to Home widgets through route coordinator. Sync only when enabled (15s), on schedule/note/focus changes, no animation-frame network. Local Wi-Fi bridge remains available separately.

Verification: failing-first video regression + auth/pair/schedule/expiry/action/privacy tests; native URL/path bounds; no overlapping native full suites; rendered desktop/phone/keyboard states; Wrangler local and live endpoint checks; optimized Windows app. Cloudflare sign-in/deployment and actual iPhone Clock/automation are separate evidence boundaries.
