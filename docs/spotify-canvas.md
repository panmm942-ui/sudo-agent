# Spotify Canvas backgrounds

Canvas is an optional background source for the expanded Spotify panel. It supplies short, silent loops, not full music videos. Some songs have no Canvas. Unavailable Canvas, mismatched track metadata, expired credentials, networking failures, and rejected authentication leave the existing song-color background visible.

In Settings → Spotify, enable Spotify Canvas background and open Canvas connection. Paste **only the value** of an `sp_dc` cookie or a short-lived access token from your own Spotify session. Do not put credentials in source files, preferences, environment files, or chat. The password input clears after saving. Native code saves the credential in Windows Credential Manager under `SudoIsland/SpotifyCanvas/v1`; status returns the saved credential type, never its value. Disconnect removes that credential and clears cached tokens and Canvas results. “Credential saved” describes local storage and does not claim successful Spotify authentication.

The cookie exchange follows the currently documented unofficial token protocol. It retrieves a bounded public challenge dictionary from the fixed `xyloflake/spot-secrets-go` raw GitHub URL without Cookie or Authorization headers, computes HMAC-SHA1 TOTP using Spotify's server clock, and sends the cookie only to `https://open.spotify.com/api/token`. Challenge rotation, account restrictions, and Spotify changes can break this exchange. A manually supplied access token avoids that exchange, expires normally, and needs manual replacement. There is no automatic browser-cookie access, browser login, third-party Canvas proxy, or Node server.

Windows media sessions provide titles, artists, albums, and duration rather than Spotify track IDs. Opting into Canvas sends that metadata to Spotify's authenticated search API, requires a matching normalized title and artist and a duration within five seconds when available, then requests the matched Spotify URI from the Canvas protobuf endpoint. Ambiguous or differently credited tracks may fall back to color. Results are limited to 32 tracks with a one-hour positive cache and five-minute missing-result cache. Only HTTPS MP4 URLs on the exact `canvaz.scdn.co` host are accepted, with no user information or nondefault port.

The caller must request a track only while video is enabled and the Spotify panel is expanded and visible; pass `null` on collapse, tab changes, or hide. The frontend immediately clears its media source and ignores stale replies. Native cancellation invalidates the current generation; an already-running HTTP request may finish its eight-second timeout, but cannot continue the old request chain or publish a late result. Native requests are serialized and response sizes are capped. Canvas elements must be unmounted when inactive so no video decoding continues offscreen.

The implementation is independent code using the endpoint names and protobuf field numbers published by [Paxsenix0/Spotify-Canvas-API](https://github.com/Paxsenix0/Spotify-Canvas-API), its [authentication service](https://github.com/Paxsenix0/Spotify-Canvas-API/blob/main/services/spotifyAuthService.js), and its [protocol definition](https://github.com/Paxsenix0/Spotify-Canvas-API/blob/main/proto/_canvas.proto). No repository implementation was copied. Its README calls the project MIT while the repository license metadata identifies GPL-3.0; no assumption of MIT compatibility was made.

Tests cover RFC HMAC/TOTP output, strict source URL validation, bounded protobuf parsing, track matching, metadata deduplication, cancellation, stale replies, and safe failure. An unsigned live check on 2026-11-04 returned 400 for the challenge-free token route, 403 for the legacy access-token route, and 401 for authenticated track search, as expected without credentials. Successful account authentication, track resolution, and live Canvas playback require the user's connection and are not established by those checks.
