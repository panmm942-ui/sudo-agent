Sudo / iPhone Clock

Your routine.
In iPhone Clock.

This is a manual Apple Shortcuts recipe. It is not an installable Shortcut. Build it once in the Shortcuts app, test it manually, then add automation triggers. Action names can differ by iOS language/version; search the Clock actions and use the equivalent name shown on your phone.

Before the first run: publish a schedule from Sudo on your PC with Online companion enabled. Your phone uses the private HTTPS service; it does not need the same Wi-Fi as your PC. The service can provide stored alarms while your PC sleeps, within the published coverage shown above. The feed refuses expired or insufficient coverage. Do not share this key: it grants access to your companion.

1. Save these exact values

In Shortcuts create a shortcut named Refresh Sudo Alarms. Start with three Text actions followed by Set Variable:

FeedURL



PairingKey
Use your phone capability key. Keep it private, including in screenshots and exported Shortcuts.


OwnerPrefix (include the spaces and final middle dot plus space)


Only alarms whose complete label starts with this exact installation prefix belong to this connection. Never delete by the word “Sudo” alone. Do not rename unrelated alarms to use this prefix.


2. Fetch and validate before touching Clock


    

  1. Add URL with FeedURL. Add Get Contents of URL: method GET, header Authorization = Bearer [PairingKey]. The space after Bearer is required. Set its output variable to Manifest. Do not add an Origin header. If this action fails, the shortcut must stop; keep all Clock changes after it.
    2. 

  2. Use Get Dictionary from Input on Manifest, then Get Dictionary Value for these keys: schema, ownerPrefix, utcOffset, timeZone, revision, generatedAt, validUntil, alarmCount, alarms, ackUrl. Save each as a variable. Use the dictionary output for every key lookup, not the output of the previous lookup.
    3. 

  3. Add If checks. If schema is not exactly sudo.iphone-alarms.v1, or ownerPrefix differs from the saved OwnerPrefix, or any required field is missing, use Show Alert then Stop This Shortcut (or Stop and Output). Check revision is nonempty and timeZone is nonempty. Check ackUrl exactly equals . Do not use a URL supplied by an unvalidated response.
    4. 

  4. Create a Date action set to specified date 1970-01-01T00:00:00Z; save as Epoch. For each numeric millisecond field, use Calculate to divide by 1000, then Adjust Date to add that many seconds to Epoch. Save the converted dates as GeneratedDate and ExpiryDate. Use Current Date as CheckNow. Stop unless GeneratedDate is no more than 5 seconds after CheckNow, no more than 90 seconds before it, ExpiryDate is after CheckNow, and no more than 90 seconds after GeneratedDate. Use Adjust Date to build comparison dates, then If to compare them. Failed numeric/date conversion must stop.
    5. 

  5. Use Format Date on CheckNow, date format Custom, format string xxx (three lowercase x characters). Keep the phone’s current time zone. This produces an offset such as +02:00, including +00:00 at UTC. Stop unless it exactly equals the manifest utcOffset. A phone in another time zone needs a fresh compatible setup; importing local PC times would be wrong.
    6. 

  6. Add Get Dictionary Value on the original Manifest dictionary, choose All Keys, and stop unless the result contains alarms and alarmCount. Require alarmCount to be a number between 0 and 1024. Use Count on the retrieved alarms and stop unless it equals alarmCount. Do not replace a missing field or failed conversion with an empty list. The service supplies alarms as a JSON array; for each nonempty item, Get Dictionary from Input must succeed. Add Repeat with Each item in alarms. Get dictionary keys label, time, at from that Repeat Item. Stop if the label does not begin with OwnerPrefix, if time is missing, or at is not a number. Convert at milliseconds to AlarmDate using the Epoch method above. Get a new Current Date; require AlarmDate to be more than 60 seconds ahead and at most 24 hours ahead. Format AlarmDate as custom HH:mm (24-hour hours; choose English (United States) locale if necessary). Require it to equal time. Format AlarmDate as xxx and require it to equal the manifest offset. Any failure: alert and stop before Clock actions. End Repeat.
    7. 



An empty, valid alarms list means Sudo has no routine alarms in the upcoming window. A failed request, missing list, malformed response, stale snapshot or time-zone mismatch is not an empty schedule.


3. Replace only this installation’s alarms


Create the new alarms before deleting the old ones. If creation stops partway through, old alarms remain, and some new duplicates may also remain. Run the shortcut again after fixing the problem. Never move deletion ahead of creation.


    

  1. Add the Clock action Get All Alarms (or the equivalent Find Alarms action without filters). Save this exact result as BeforeImport. This is the captured old list; never refresh this variable during deletion.
    2. 

  2. Use the validated alarmCount, save as ExpectedCount. Add Number 0, save as CreatedCount.
    3. 

  3. Repeat with Each item in manifest alarms. Get label and at from that item and convert at to AlarmDate again. Recheck a fresh Current Date: AlarmDate must still be more than 60 seconds and at most 24 hours ahead, and manifest ExpiryDate must still be in the future. If any check fails, alert and stop before creating that alarm; old alarms remain.
    4. 

  4. Inside that Repeat add Clock Create Alarm / Add Alarm. Set its time to the AlarmDate variable (tap the time field to insert a variable), label/name to the item’s label, Repeat = Never, and enabled/on if that option exists. Expand the action’s additional options to verify these settings. Do not select weekdays or use a recurring alarm. The date supplies the local time; ordinary Clock alarms ring at that time’s next occurrence and do not store a future calendar date.
    5. 

  5. Require the Create Alarm action’s returned Alarm to have a value; otherwise stop. Use Calculate CreatedCount + 1, then Set Variable CreatedCount. End Repeat. Stop unless CreatedCount equals ExpectedCount. If your iOS Clock action does not return an Alarm object, verify the created result manually and do not enable unattended automation until that behavior has been checked.
    6. 

  6. Now Repeat with Each item in the saved BeforeImport list. Tap that Alarm variable and select its Label / Name detail. Add If its label begins with the exact saved OwnerPrefix, then add Clock Delete Alarms with only that Repeat Item as input. Never pass All Alarms or the full BeforeImport list to Delete. End If, End Repeat. Any error or cancelled deletion must stop before the acknowledgement. iOS may ask you to confirm deletion; inspect the affected labels before accepting.
    7. 



4. Acknowledge only a finished import


    

  1. After both Repeat blocks finish successfully, add URL with , then Get Contents of URL. Method POST, header Authorization = Bearer [PairingKey], Request Body = JSON. Add revision as Text with the manifest revision variable, and createdCount as Number with CreatedCount. Shortcuts supplies Content-Type: application/json. Do not encode the whole body as a quoted string.
    2. 

  2. Add Show Notification: Imported [CreatedCount] Sudo alarms. A successful acknowledgement has an empty response. If the acknowledgement fails, the phone may already contain the new alarms; Sudo deliberately keeps “Last imported” unchanged. Run again to reconcile.
    3. 



5. Test, then automate


First take note of an unrelated alarm in Clock. Run the shortcut manually, approve Shortcuts network/Clock prompts, and inspect Clock: imported labels begin with , times match Sudo, Repeat is Never, and the unrelated alarm remains unchanged. Run a second time: only one current set of this installation’s alarms should remain. Test an actual alarm on the phone. In the companion, “Clock import reported” means only that the Shortcut reported completion. Neither status proves that the phone rang.


In Shortcuts → Automation, add Time of Day, choose a daily refresh time within your stored schedule coverage, and run Refresh Sudo Alarms. You can also add a Wi-Fi automation and run the same shortcut when you join your home network; the service itself works over the Internet. Choose Run Immediately where your iOS version offers it; some Clock actions and deletion permissions can still require interaction. Test both triggers on your phone before relying on them. Run the shortcut manually after changing your Sudo schedule or moving time zones.


Alarms less than a minute away are excluded; use Sudo on the PC for imminent reminders. Only the next 24 hours are imported; later alarms need another successful refresh. The PC does not push edits instantly. Once imported, the iPhone rings independently of the PC. Disconnecting your PC stops fresh schedule publishing; stored coverage can remain until it expires. Revoking the phone key stops future authenticated imports but leaves already-created phone alarms in Clock; remove this installation’s prefixed alarms there if desired. This recipe does not change your other alarms, Sleep schedule, ringtone, system alarm volume or snooze preferences.


Connection troubleshooting
Check the HTTPS service address and phone key against this page. A revoked key needs a fresh pairing from your PC and an updated key in every Shortcut. If the feed reports expired or missing coverage, open Sudo on your PC and reconnect Online companion to publish a fresh schedule. The phone must have Internet access, and stored coverage must include the next 24 hours. After a time-zone change, check the phone and PC offsets and refresh before importing. Never treat a network error or expired schedule as an empty alarm list.


Phone import, action availability and ringing require testing on your iPhone. No signed/importable Shortcut artifact is supplied by this page.
